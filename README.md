# 九九バトル

小学 2 年生が、学校で九九が始まる前に全部言える状態になることを目的とした PWA。

報酬をアプリの中に置かない。教室で「これ知ってる」となる体験を報酬とする。
設計の方針と判断の根拠は `docs/design-notes.md` を参照。

## 現在の実装範囲（第 1 版）

| 項目 | 状態 |
| --- | --- |
| 九九のタイムアタック（10 問） | 実装済み |
| 段ごとの解放（順序は設定で変更可能） | 実装済み |
| 問題の音声読み上げ | 実装済み |
| 親子で同じ問題セット。親の記録が常に表示 | 実装済み（同一端末内） |
| 段ごとの遅さ・誤答の可視化（親のみ） | 実装済み |
| 問題文・世界観の差し替え | 実装済み（JSON 3 テーマ） |
| 親子で端末が分かれた場合の記録同期 | 未検証（Supabase アダプタは実装済み） |
| プッシュ通知 | 未実装 |

## 起動

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # 本番ビルド
npm run typecheck  # 型チェック
npm run icons      # アイコン PNG の再生成
```

## iPhone への設置

ブラウザのブックマークでは開かれない。ホーム画面に置くこと。

1. デプロイ先の URL を子どもの iPhone の Safari で開く
2. 共有メニューから「ホーム画面に追加」
3. YouTube や Roblox と同じ列に配置する

アイコンと名称は意図的にゲーム側へ振っている。
「勉強」「ドリル」「学習」という語は画面のどこにも出していない。

## 構成

```
src/
  app/
    page.tsx          ホーム。相手の選択と、親の記録の常時表示
    play/             タイムアタック本体
    parent/           親専用画面（段の解放、弱点、着せ替え）
    manifest.ts       PWA マニフェスト
  components/
    PlayScreen.tsx    出題・判定・計測
    Result.tsx        結果。答えをタップで聞き返せる
    StageInsights.tsx 子どもの状態（親のみ）
    ParentGate.tsx    親画面の入口
  lib/
    kuku.ts           出題の組み立てと重み付け、入力判定
    yomi.ts           九九の唱え方テーブル
    speech.ts         Web Speech API のラッパ
    themes.ts         着せ替えの読み込み
    storage/          保存層（local / supabase）
  data/themes/*.json  テーマ定義
```

## 設計上、意図的にそうしている点

実装を変更する際は以下を壊さないこと。いずれも設計メモ上の判断に対応する。

- **間違いで減点しない。** ライフ、連続正解、赤い×は持たない。
  誤答は出題の重み（`lib/kuku.ts` の `weightOf`）にのみ反映する。
- **タイマーは考えている時間だけを測る。** 誤答時の解説中は計測を止める。
  間違いが記録を悪化させると、減点しない方針と矛盾するため。
- **連続日数とプレイ時間を記録も表示もしない。** 途切れた日に開かなくなる理由を作らない。
- **苦手を子どもに見せない。** 段ごとの遅さと誤答率は親画面にのみ表示する。
- **解放は 1 段ずつ。** 未習の段を出すと「わからない」だけが残る。
  既定の順序は 5, 2, 3, 4, 6, 7, 8, 9, 1 だが、学校の進度に合わせて親が並べ替える。
- **1 回 10 問。** 物足りないくらいの長さに保つ。
- **ポイント・コイン・ガチャを置かない。** 見た目の解放を追加する場合も、
  達成と無関係な配布にはしないこと。

## 音声について

問題は平読み（「ろく かける なな」）、答えは九九の唱え方（「ろくしちしじゅうに」）で読み上げる。
唱え方は覚える対象そのものなので、誤答時と結果画面のタップ時にのみ再生する。
読みのテーブルは `src/lib/yomi.ts` にある。

iOS Safari では最初の発話がユーザー操作起点である必要があるため、
「はじめる」のタップ時に `primeSpeech()` を呼んでいる。

## テーマの追加

`src/data/themes/` に JSON を置き、`src/lib/themes.ts` の `THEMES` に追加する。
問題文の着せ替えは LLM で生成してよいが、生成結果は JSON として保存し、実行時には呼ばない。
応答速度と費用の両面で、毎回呼ぶ形にはしないこと。

敵の名前は親画面から編集でき、その場で反映される。
子どもに決めてもらうための項目であり、この用途を想定して即時反映にしている。

## 親子で端末が分かれる場合（未検証）

第 1 版は端末内（localStorage）で完結している。親も子の端末で親画面から記録を作る。

別端末に分ける場合は Supabase を有効にする。

```bash
cp .env.example .env.local
# NEXT_PUBLIC_SUPABASE_URL と NEXT_PUBLIC_SUPABASE_ANON_KEY を設定
```

`supabase/schema.sql` を Supabase の SQL エディタで実行し、
親子それぞれの端末で同じ「家族の合言葉」を設定する。

anon キーは公開されるため、家族ごとの分離は RLS とリクエストヘッダ `x-family-code` で行う。
合言葉は推測されにくい長い文字列にすること。

**この経路は実際の Supabase プロジェクトに対して未検証である。**
有効化する際は、まず記録が相互に見えることを確認すること。

## 成功の判定

| 問い | 見るもの | 実装 |
| --- | --- | --- |
| 開かれているか | 親が言わずに開いた回数 | 親画面「この 7 日で開いた回数」 |
| 覚えたか | 学校で九九が始まったときに既に言えたか | アプリ外で確認する |
| 態度が変わったか | 九九以外の勉強に対する反応 | アプリ外で確認する |

連続日数やプレイ時間は成功指標にしない。
増やそうとすると子どもの時間を奪う方向に働き、目的と逆行する。
