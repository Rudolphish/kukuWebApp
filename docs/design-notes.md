# 九九アプリ 設計メモ

小学 2 年生の子どもが、勉強を嫌いにならず、できれば好きになるための最初の一手。
実装は別セッションで行う前提の、方針と判断の記録。

## 前提（確認済み）

| 項目 | 内容 |
| --- | --- |
| 対象 | 小学 2 年生 |
| 端末 | 子ども専用の iPhone |
| 九九 | 未習。ただし風呂に九九シートが貼ってあり、存在と形式は知っている |
| よく見るもの | ひまわりチャンネル、ちろぴの（マイクラ系の子ども向け） |
| よく遊ぶもの | Roblox |
| 目的 | 勉強時間を増やすことではなく、勉強への態度を変えること |

## 中心となる考え

**学校で九九が始まったとき、もう全部言える状態にする。**

報酬をアプリの中に置かない。教室で「これ知ってる」となる体験を報酬にする。
作り物のポイントではなく現実の達成であり、しかも 2 学期中という自然な締切がある。

九九が未習であることは不利ではなく、この設計の前提そのものである。
既に習っている題材では「先に知っている快感」が作れない。

## 設計の柱

### 1. 子どもの iPhone のホーム画面に置く

PWA として作り、Safari の「ホーム画面に追加」で置く。
**ブラウザのブックマークでは開かれない。** YouTube や Roblox と同じ列に、
同じ見た目のアイコンで並んでいる必要がある。

アイコンと名前は完全にゲーム側へ振る。「勉強」「ドリル」「学習」という語を
画面のどこにも出さない。小 2 でもその看板には敏感である。

### 2. 親子対戦は非同期にする

子ども専用端末であるため、親が隣にいる前提は置けない。

- 親の記録（タイムと正答数）が常に表示されている状態に、子どもが一人で挑む
- 記録が抜かれたら親へ通知が飛ぶ。逆に親が更新したら子へ「挑戦状」が届く
- 通知は 1 日 1 回までに制限する。頻繁だと逆効果になる

**親は手加減しない。** 九九であれば親は本気で速いので、子どもが勝つには
本当に覚えるしかない。しかし親もミスをするため「勝てた」が実際に起きる。
これはコインやバッジが届かない場所である。手加減した瞬間に見抜かれる。

### 3. 読ませない。音声で出す

小 2 は読字自体が負荷である。文字だけの画面は、内容と無関係に閉じられる。

九九は本来「唱えて覚える」ものであり、風呂の九九シートもその形式である。
音声読み上げは装飾ではなく、学習方法そのものと一致する。

- 問題を音声で読み上げる（Web Speech API で日本語音声が使える。無料）
- 答えも声で聞ける
- ひまわりチャンネルやちろぴのは「語りかけ」の形式であり、
  子どもが慣れているのはこの形である

### 4. 作る側に巻き込む

Roblox をやっている子は、ゲームが誰かに作られていることを既に知っている。
マイクラ系の動画を見ているのも同様で、この年齢の関心は「作る」側にある。

小 2 に Lua や JavaScript を書かせるのは無理があるため、役割を分ける。

> **子どもがデザイナー、親が実装者。**

- 「敵の名前を決めて」「問題文の世界観を考えて」を子どもに投げる
- そのアイデアが**翌日には動いている**状態にする
- LLM を使えば問題文の着せ替えは短時間でできるため、当日反映も可能

自分の考えたものが動いて遊べる経験は、この年齢ではかなり強い。
そして翌日には別のアイデアを持ってくる。

## 題材の扱い

### 段の解放順は学校に合わせる

**未習の段をいきなり出すと「わからない」だけが残り逆効果になる。**

一般に日本の教科書では 5 の段から始めることが多い（規則が見えやすいため）。
ただし教科書と学校の進度によって順序は異なるため、**順序を設定で変えられる
作りにしておく**こと。学校で今どこをやっているかに合わせるのが最優先である。

先取りを狙う場合も、解放は 1 段ずつにする。全段を最初から開けない。

### 間違いは減点しない

間違えた問題を「情報」として扱い、出題頻度を上げるだけにする。
連続正解が切れる、ライフが減るといった演出は入れない。
小 2 が一度「自分は苦手だ」と結論づけると、そこから戻すのは難しい。

### 世界観の着せ替え

同じ九九でも、文脈があるだけで別物になる。

> ダイヤモンドを 6 個ずつ、7 人のなかまに配ります。ぜんぶで何個いる?

**この着せ替えを無限にできることが LLM の最も有効な使い方である。**
今日はマイクラ、明日は Roblox、来週は違うもの。既製のドリルは書き換えられない。

親が作ったものは飽きるのも速い。飽きたら着せ替えられる作りにしておくことが、
そのまま寿命の対策になる。

## やらない方がいいこと

- **ポイント・コイン・ガチャで釣る。** 短期は動くが「ごほうびがないとやらない」へ
  変わる危険がある。元々あった興味まで報酬目当ての作業に置き換わりうる
- **未習の段を出す**（上記）
- **文字だけの画面**
- **「勉強」を名乗る**
- **長時間プレイを推奨する。** 1 回 1 分で終わる長さにする。物足りないくらいで
  ちょうどよい。もう一回やりたくなる方が、疲れて閉じるよりよい
- **連続日数を大きく見せる。** 途切れた日に開かなくなる理由を作ってしまう

### 見た目の解放について

九九を覚えるとアバターのパーツが増える形は、Roblox の中核体験と重なるため
効果が期待できる。ただしこれは「ポイントで釣る」に近づく危険もある。

**進度の可視化として設計すれば健全**（5 の段を覚えた証として帽子が増える）だが、
**達成と無関係にランダムで配ると餌になる**。ガチャにしないこと。

## 第 1 版のスコープ

- 九九のタイムアタック。10 問で 1 分以内に終わる
- 段ごとの解放。最初は 1 段だけ
- 問題の音声読み上げ
- 親子で同じ問題セット。親の記録が常に見えている
- どの段が遅いかが親には見える（子どもには苦手を強調して見せない）
- 問題文の世界観は後から差し替えられる作りにしておく

**作り込まない。** 早く子どもの反応を見ることが最優先である。
反応を見る前に大きく作ると外す。

## 成功の判定

作る前に決めておく。

| 問い | 見るもの |
| --- | --- |
| 開かれているか | 親が言わずに開いた回数 |
| 覚えたか | 学校で九九が始まったときに、既に言えたか |
| 態度が変わったか | 九九以外の勉強に対する反応 |

**連続日数やプレイ時間を成功指標にしない。** それらは増やそうとすると
子どもの時間を奪う方向に働き、目的と逆行する。

3 番目が本来の目的だが、最も測りにくい。1 と 2 を先に見る。

## 技術的な選択

既存の資産をそのまま使える。

- Next.js / Vercel（gamers-highlight と同じ構成）
- Supabase（親子のスコア保存）
- PWA としてホーム画面へ追加
- 音声は Web Speech API（無料、iOS Safari で日本語音声が使える）
- 問題文の生成は LLM。ただし**毎回呼ばない**。生成した問題文は保存して使い回す
  （応答速度と費用の両面で。小 2 は待たされると閉じる）

Roblox の中に作る案は魅力的だが第 2 段階とする。
Roblox Studio と Lua の学習コストを払う前に、そもそも食いつくかを確かめたい。

## 未確定・確認が必要なこと

- 学校の教科書と、九九の段の学習順序
- 子どもの iPhone の使用に関する家庭内の取り決め（時間帯、通知の可否）
- 親側の端末で記録を更新する手段（親も同じ PWA を使うか、別画面にするか）
- PWA の通知が iOS でどこまで安定して届くか（バージョンと設定に依存する。
  通知に依存した設計にせず、無くても成立する形にしておくのが安全）
