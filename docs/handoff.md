## いまブロックしていること

**`FAMILY_CODE` が古い 6 文字のまま届く。**

本人は 24 桁に更新したと言っているが、環境から届く値は 6 文字だった。
切り分け済みの事実は次のとおり。

| 確認したこと | 結果 |
| --- | --- |
| シェルのプロファイルによる上書き | 定義なし |
| `.env.local` の残存 | ファイル自体が存在しない |
| エクスポートの有無 | `declare -x` で確認、エクスポート済み |
| node が見る値 | `process.env.FAMILY_CODE` も 6 文字 |
| 環境の取り違え | セッションの環境は「九九アプリ」で正しい |
| 他 2 つの環境変数 | 正しい長さで届いている（注入の仕組みは正常） |

つまり**保存されている値そのものが 6 文字**という状態だった。
未確認の筋は 2 つ。

1. `FAMILY_CODE` が Environment variables と Network secrets の両方にあり、
   24 桁を入れた側が負けている
2. 値の更新が反映されず、削除して作り直す必要がある

### 新しいセッションで最初にすること

```bash
printf 'FAMILY_CODE = %s 文字\n' "${#FAMILY_CODE}"
```

**20 文字以上なら解決している。** 6 文字ならまだ上の 2 つを疑う。

`FAMILY_CODE` は 1 回設定すれば端末に保存されるものなので、長くても手間は増えない。
anon キーは公開前提で、実質の秘密はこの合言葉だけ。短いと総当たりの範囲に入る。

### 続けて確認すること

```bash
npm run stories -- pending
```

`注文なし` または注文の一覧が返れば、鍵とネットワークは通っている。

ただし**これは 3 か所の一致を保証しない。** 合言葉は次の 3 か所で揃っている必要がある。

| 場所 | 用途 |
| --- | --- |
| 環境変数 `FAMILY_CODE` | 話を作る側 |
| 子どもの端末の親画面 | アプリの読み書き |
| 親の端末の親画面 | 記録の同期・親画面の閲覧 |

**食い違っていてもエラーは出ず、`注文なし` が返るだけ。** これが最も気付きにくい壊れ方。
唯一の確実な確認は、端末から実際に 1 件注文して `pending` に出るかを見ること。

## 環境の癖（詰まったときに読む）

- 環境変数とネットワーク設定は、**セッションを作り直さなくても反映される**
  （アプリの再起動で入る）。古いセッションだからという理由で片付けない
- Supabase MCP の `execute_sql` で **書き込みを含む SQL は確認ダイアログが出る**。
  応答がないと 60 秒で切れる。3 回試して届かなかったことがある。
  そのときは本人に Supabase の SQL Editor で流してもらうのが早い
- `apply_migration` に `drop policy if exists` を入れると破壊的文として確認を求められる。
  新規作成なら drop を外せば通る
- `npm run lint` は ESLint の設定が無いため対話プロンプトで止まる。
  今回の変更とは無関係の既存の状態。CI に乗せるなら設定ファイルが必要
- レイアウトの確認は `npm run layout-check`（6 つの画面サイズで検証する）
