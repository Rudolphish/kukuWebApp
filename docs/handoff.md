## 解決済み: `FAMILY_CODE` の長さ

2026-10-27 の新しいセッションで、環境から届く `FAMILY_CODE` が 24 文字であることを確認した。
以前は 6 文字のまま届いていたが、原因の特定（二重登録か、反映漏れか）はできていない。
再発した場合は、Environment variables と Network secrets の両方に同名の値がないかを最初に疑う。

確認方法（値そのものは表示しない）:

```bash
printf 'FAMILY_CODE = %s 文字\n' "${#FAMILY_CODE}"
```

`FAMILY_CODE` は 1 回設定すれば端末に保存されるものなので、長くても手間は増えない。
anon キーは公開前提で、実質の秘密はこの合言葉だけ。短いと総当たりの範囲に入る。

同セッションで `npm run stories -- pending` が `注文なし` を返すこと、
テスト 69 件の通過、型チェックの通過も確認済み。

## 合言葉を端末へ渡す QR（2026-10-27 追加）

親画面の「べつの端末とつなぐ」に「子どもの端末で開く QR を出す」を追加した。
子どもの端末で読み取ると `/join` が開き、「つなぐ」を押すと合言葉と「子どもの端末」が設定される。

- 合言葉は URL のフラグメントで渡す（サーバに送られない）。`/join` は読んだ直後に消す
- 書き込みは「つなぐ」を押してから。親が自分の端末で読み取っても勝手に持ち主が変わらない
- 実装は `src/lib/join.ts`・`src/components/JoinQr.tsx`・`src/app/join/page.tsx`、
  テストは `tests/join.test.ts`
- Playwright で、親画面の QR を実際に読み取り（jsQR）、子どもの端末側で
  合言葉と持ち主が設定されるところまで確認済み（Supabase への通信は遮断して実施）

**未確認の点:** iPhone では、ホーム画面に追加したアプリと Safari とで保存領域が別になる場合がある。
既にホーム画面にアプリがある端末では、QR で開いた Safari 側にだけ合言葉が入る可能性がある。
実機での確認が必要。

## 環境の癖（詰まったときに読む）

- 環境変数とネットワーク設定は、**セッションを作り直さなくても反映される**
  （アプリの再起動で入る）。古いセッションだからという理由で片付けない
- Supabase MCP の `execute_sql` で **書き込みを含む SQL は確認ダイアログが出る**。
  応答がないと 60 秒で切れる。3 回試して届かなかったことがある。
  そのときは本人に Supabase の SQL Editor で流してもらうのが早い
- `apply_migration` に `drop policy if exists` を入れると破壊的文として確認を求められる。
  新規作成なら drop を外せば通る
- `npm run lint` は ESLint の設定が無いため対話プロンプトで止まる。
  今回の変更とは無関係の既存の状態。CI に乗せるなら設定ファイルが必要
