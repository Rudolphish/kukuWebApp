# 九九バトル 第 3 段階 設計メモ — ランクと見た目

`design-notes.md` と `story-mode-design.md` の続き。
実機で子どもに触らせた結果を受けて決めたことの記録。

採用した案と、検討して採らなかった案の両方を残す。理由まで書いておくことで、
後から同じ案を思いついたときに検討をやり直さずに済む。

## 発端

子どもに実際に触らせた。結果は次のとおり。

- **バトルは好感触。タイムアタックが効いていた。**
  親の記録を抜くという動機づけは、設計メモの柱 2 の賭けどおりに働いた
- **見た目が古い。** 開きたくなる画面になっていない
- 要望として「タイムに応じたランク（〇〇秒以内でゴールドなど）」

最初の 2 つは観察、3 つ目は本人からの要望である。この区別は残しておく。
観察のほうが強い情報であり、要望はその場の思いつきを含みうる。
今回は 3 つ目が 1 つ目（タイムが効いている）と整合したので採った。

## 判断 1: ランクは置いてよい。ただし餌にはしない

設計メモの「やらない方がいいこと」に
**「ポイント・コイン・ガチャで釣る」**がある。ランクはこれに当たるか。

当たらない。同じ項は続けてこう書いている。

> **進度の可視化として設計すれば健全**（5 の段を覚えた証として帽子が増える）だが、
> **達成と無関係にランダムで配ると餌になる**。ガチャにしないこと。

禁じているのは「達成と無関係な配布」である。
タイムに応じたランクは達成そのものの尺度であり、達成とは別に配る餌ではない。
ゴールドを取るには実際に速く正確に答えるしかなく、そこに運も通貨も挟まらない。

そのうえで、この仕組みが壊してはいけないものが 2 つある。

### 壊してはいけないもの 1: 減点しない

最下位のランクを失敗の名前にしない。
10 問終えた時点で必ず「クリア」が付く。**付かないランクを作らない。**

「ランクなし」を作ると、それは不合格の別名になる。
設計メモの「間違いは減点しない」は、ライフや赤い× だけの話ではない。
結果画面に「あなたは何も取れなかった」と出ることも減点である。

### 壊してはいけないもの 2: 苦手を子どもに見せない

結果画面に出すのは、常に**「1 つ上のランクまであと何秒」だけ**にする。

クリアにいる子に「ゴールドまであと 23 秒」と出すと、それは苦手の通知になる。
ブロンズまであと 3 秒と出れば、それは次の 1 回の理由になる。
同じ事実でも、距離の取り方で意味が反転する。

正答数の上限で止まっているとき（9/10 でタイムはゴールド相当、など）は
秒数を出さない。速くしても上がらないので、出すと嘘になる。

## 判断 2: しきい値は段ごとに変える

**「〇〇秒以内でゴールド」を全段で同じ秒数にはできない。**

1 の段は答えが 1 桁でそのまま出てくる。9 の段は 2 桁で思い出す必要がある。
同じ秒数で測ると、1 の段は必ずゴールド、9 の段は一生ゴールドなしになる。
前者ではランクが情報を持たず、後者では存在しないのと同じになる。

1 問あたりの目標時間を 3 つの要素から組む（`src/lib/rank.ts`）。

| 要素 | 根拠 |
| --- | --- |
| 固定費 1.5 秒 | 問題を読んでキーを 1 つ押すまで |
| 2 桁なら +0.45 秒 | 押す回数が 1 回増える |
| 積の平方根に比例する想起時間 | 積が大きいほど思い出すのに時間がかかる |

想起時間には割引を入れる。

- 1 をかける問題は 0.3 倍（答えがそのまま）
- 2 と 5 の段は 0.65 倍（数えてたどれる）
- ぞろ目は 0.85 倍（覚えやすい）

結果（ふつう、10 問の合計・秒）:

| 段 | 🥇 | 🥈 | 🥉 |
| --- | --- | --- | --- |
| 1 | 15.6 | 20.3 | 26.5 |
| 3 | 21.1 | 27.5 | 35.9 |
| 5 | 21.8 | 28.4 | 37.1 |
| 7 | 23.7 | 30.8 | 40.3 |
| 9 | 24.3 | 31.6 | 41.4 |

5 の段が 4 の段より短いのは意図したとおりである（数えてたどれるため）。

**ブロンズの境目が 1 分を超えないことを単体テストで固定してある。**
設計メモの「1 回 1 分で終わる長さ」を、ランクの境目が壊してはいけない。
最下位のランクが 1 分を超える遊びを前提にしてしまうと、別の柱が崩れる。

### 段で決める。引かれた 10 問では決めない

引かれた問題でしきい値を決めると、同じ記録が結果画面とホームで
違うランクに見えることがある。段で決めれば、その段のゴールドは
**1 つの秒数として言い切れる**。言い切れることが、追いかける的になる条件である。

「速く」は的にならないが、「22.0 びょう」は的になる。だからホームに出している。

表示は切り捨てる。22.09 秒を四捨五入して「22.1 びょう」と出すと、
22.1 秒で走った子がゴールドにならない。**表示した秒数で必ず取れること**を優先する。
この不変条件は単体テストで全段・全きびしさについて確かめている。

## 判断 3: 速いだけではゴールドにしない

ゴールドは「全部あっていて、しかも速い」の名前にする。
タイムだけで決めると、覚えていなくても当てずっぽうで連打した方が速くなる。
それは九九を覚えるアプリとして本末転倒である。

正答数で上限をかける。落とした分だけ上限が下がる。

| 正答数 | 届く上限 |
| --- | --- |
| 10/10 | ゴールド |
| 9/10 | シルバー |
| 8/10 | ブロンズ |
| 7 以下 | クリア |

下げるのは**上限だけ**で、ランク自体は必ず付く。ここが減点との境目である。

## 判断 4: 厳しさは親が 1 段ずらせる

**実際の子どもの速さは、遊ばせてみるまで分からない。**
固定値で決め打つと、速ければ常にゴールドで意味がなくなり、
遅ければ一生ゴールドなしで存在しないのと同じになる。

親画面に「きびしめ / ふつう / ゆっくりめ」（0.85 / 1.0 / 1.25 倍）を置いた。
段ごとの秒数も表で見せているので、親は何を変えているかを把握できる。
段の並べ替えや敵の名前と同じで、**合わなければ親が直せる**という既存の筋に沿う。

## 判断 5: 見た目は「奥行き」で直す

「ダサい」の中身を、直せる形に分解する。元の画面は次の状態だった。

- 面がすべて同じ平らな 1 色に 1px の枠。設定画面に見える
- 入場も待機もアニメーションが無く、開いた瞬間から静止している
- 数字が主役の画面なのに、数字が他の文字と同じ扱い

直し方は 3 つ。

1. **奥行きを与える。** 面に上端の光（`inset 0 1px 0`）と影とグラデーションを入れる。
   背景は画面に固定した放射グラデーションにする（中身がどれだけ伸びても描画量は一定）
2. **開いた瞬間に動かす。** 中身が順に起き上がる（`.rise`、`--i` で段をずらす）。
   相手はゆっくり上下する。「はじめる」には遅い光沢を往復させる
3. **数字を主役にする。** 問題文に発光を乗せ、等幅にして桁が動いても横に揺れないようにする

**色はすべてテーマ変数から導出する。** テーマを 1 つ足すたびに
見た目の調整が要る状態にしない。accent の上に乗せる文字色も
`color-mix(in srgb, var(--bg) 72%, #000)` で導出しており、
緑・紫・青の 3 テーマすべてで沈まないことを確認している。

## 判断 6: ホームの外枠を画面の高さに固定する

実機で測ったところ、**ホームの中身が画面の高さを越えていた**。
これは今回の変更で入った不具合ではなく、**第 1 版から存在していた**
（iPhone SE 相当で 217px、375×667 で 96px 超過）。
越えた分は文書のスクロールになるので、いちばん下の「はじめる」が画面の外へ出る。

**開いて最初に押すボタンが見えていないのは、押せないのと同じである。**

直し方として、要素を削って収める方向は採らなかった。
端末の高さは今後も分からないままなので、同じ問題が別の端末で再発する。

代わりに構造で解いた。外枠を画面の高さに固定し（`.app[data-fit='true']`）、
あふれる可能性があるのは中身（`.scrollArea`）だけにする。
これで端末の高さがどうであっても「はじめる」は必ず画面の中にある。

そのうえで、画面の高さに応じた圧縮を 3 段（790px / 620px / 580px 以下）置き、
よくある端末では実際にはスクロールが起きないようにした。

### 守る条件を先に決めてから測る

「収まった」では確かめたことにならない。次を不変条件として全サイズで測った。

| 条件 | なぜ |
| --- | --- |
| 文書がスクロールしない | 「はじめる」が画面外に出ない |
| 「はじめる」が全体見えている | 最初に押すボタン |
| 段カードが全部見えている | 相手を選ぶのにスクロールさせない |
| きろくの 2 行とも見えている | 親の記録の下に自分の記録がある状態が動機そのもの |
| 見切れている要素が無い | 潰れて収まるのは収まったうちに入らない |

320×568 / 360×640 / 375×667 / 390×844 / 414×736 / 430×932 の 6 点で確認した。
1 点で測って直ったと報告したのが前回の失敗なので、ここは必ず複数点で測る。

実際、途中で 2 回とも**1 点では見えない壊れ方**を踏んでいる。

- 縦の flex で中身が既定どおり縮み、キャラの箱が潰れて頭が切れた
  （→ `.scrollArea > * { flex-shrink: 0 }`）
- 狭い端末で「おとうさん」が 1 文字ずつ縦に折れ、自分の記録が画面外へ出た
  （→ 横幅の問題は横幅のクエリで解く。364px 以下では記録からランクの札を落とす）

## 検討して採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| しきい値を自己ベストに追従させる | ゴールドが常に手の届かない所に逃げる。構造としては「報酬で釣る」と同じ踏み車になり、しかもゴールドが何も意味しなくなる。固定値なら「5 の段のゴールド」は一生同じ達成を指す |
| 全段で同じ秒数にする | 1 の段は必ずゴールド、9 の段は一生ゴールドなし。要望の文面（「〇〇秒以内でゴールド」）には最も近いが、そのまま作ると機能しない |
| 最下位を「ランクなし」にする | 不合格の別名になる。減点しない方針と正面から衝突する |
| ランクに応じて見た目を配る（色・帽子など） | 設計メモが条件付きで認めている形ではあるが、今は配る物の側を作り込む段ではない。ランクが実際に効くかを先に見る |
| 結果画面にゴールドまでの距離を常時出す | 下位にいる子には苦手の通知になる。1 つ上までの距離だけにする |
| ランクをストーリーモードにも出す | ストーリー中の戦いは時間を競っていない。`story-prompt.md` でも話の中に点数・ランクを出さないことにしている |
| ドット絵フォント・レトロ UI で「ゲームらしく」する | 本人が既に「フォントは普通でいい。ドット文字とか普段読まない」と判断済み |
| 狭い端末向けに要素を削って収める | 端末の高さは今後も分からない。削る方向は別の端末で再発する。外枠を固定して中身を流す方が確実 |

## 未確定・次に確かめること

- **ゴールドが実際に取れる難しさか。** 数字は構造から組んだ推定であって、
  この子の実測ではない。1 回も取れない、あるいは毎回取れるようなら
  親画面のきびしさを 1 段ずらす。それでも合わなければ係数を見直す
- ランクが「もういちど」を押す理由になっているか。
  見るのは親画面の「この 7 日で開いた回数」であって、プレイ回数ではない
- 「はじめての ゴールド」が出た回に、子どもが反応するか
- 効果音。演出は入れたが音はまだ無い。本人が選ぶ必要がある
