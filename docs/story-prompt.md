# ストーリー生成のプロンプト

子どもが出した種を、1 本の話のデータへ落とすための雛形。
`npm run stories -- prompt <id>` が、下の本文の `【ここに子どもが言ったこと】` を
注文の中身に差し替えて出す。手で使う場合も同じ本文を使う。

検査は `npm run stories -- check <file.json>`。
**検査に落ちたら、出た指摘を直して書き直す。**

見本の形は下の「出力する JSON の形」。判断の記録は
`docs/story-authoring-design.md` の判断 9。

---

## 話の形（2026-10-27 から）

**小学生向けの小説の形**にする。はじめから順にページを読み、最後に 1 回だけ戦う。

```
ページ 1 → ページ 2 → … → ページ N → さいごの しょうぶ（戦い 1 回） → むすび（勝ち / 負け）
```

以前の「散策の形」（道を選び、場面と出会いをプールから引く）は、
場面がばらばらで筋が無く、単調だった。戦いも散策のたびに起きて、子どもが面倒がった。
散策の形の話（同梱の 2 エリアと、それまでに作った話）はそのまま遊べるが、
新しく作る話はすべてこの形にする。

---

## プロンプト本文（ここから下をコピー）

小学 2 年生が読む（聞く）、短い小説を JSON で書いてください。
九九のアプリに入る話で、話の最後に 1 回だけ、かけざんの しょうぶ が入ります。

### 子どもが言ったこと

```
【ここに子どもが言ったこと】
```

この内容を必ず話の中心に使ってください。子どもが選んだ ばしょ・でてくるもの・かんじ を
そのまま話の舞台・登場人物・雰囲気にするのがあなたの仕事です。
「なにを する」があれば、それを話の出来事の中心にしてください。

### つづきの おはなしの場合

上に「まえの おはなし」があれば、その話のつづきとして書いてください。

- 「でてくるもの」が まえの なかまなら、名前・絵文字・口調を そのまま使う
- 「ばしょ」は新しい場所にする。まえの なかまと一緒に旅に出る形にすると、つづきだと分かりやすい
- はじめの 1〜2 ページで、まえの ぼうけんに ひとこと ふれる
- まえの おはなしを 読んでいなくても 楽しめるように書く

### どんな話にするか（いちばん大事）

**絵本の説明文ではなく、小学生向けの小説として書いてください。** 単調な話は読まれません。

- **主人公をはっきり決める。** 名前があり、したいこと・こまっていることがある
- **筋を通す。** はじまり（主人公と願い）→ 事件（こまったことが起きる）→
  山場（ためしては失敗し、なかまと力を合わせる）→ 最後の しょうぶ → むすび
- **ページごとに何かが変わる。** 同じ調子の説明を並べない。
  新しい発見・ちょっとした失敗・おどろき・笑える場面を入れる
- **会話を多めに。** 登場人物がしゃべって話が進む。セリフのページは `speaker` を入れる
- **五感で書く。** におい・音・さわった感じ・色。読んでいて場面が目に浮かぶように
- **次が気になる終わり方のページを、ところどころに置く**
  （「そのとき、うしろで がさっと おとが した。」など）
- **最後の しょうぶに意味を持たせる。** 話の中で積み上がった問題が、
  かけざんの しょうぶ で決着する形にする。しょうぶの あいては悪者にしない。
  なかよくなれる相手、または いっしょに なやんでいた相手にする

### 出力する JSON の形

```json
{
  "format": "novel",
  "name": "おはなしの だいめい",
  "origin": "original",
  "cast": [
    { "name": "しゅじんこうの なまえ", "emoji": "🐱" },
    { "name": "なかまの なまえ", "emoji": "🦉" }
  ],
  "pages": [
    { "text": "じのぶん（ちのぶん）の ページ。" },
    { "speaker": "しゅじんこうの なまえ", "text": "「セリフの ページ」と いった。" }
  ],
  "boss": {
    "intro": "しょうぶの まえに よむ ページ。あいてが あらわれる。",
    "enemy": {
      "id": "boss",
      "name": "しょうぶの あいての なまえ",
      "emoji": "🦊",
      "greeting": "しょうぶの まえの ひとこと",
      "onCorrect": ["...", "...", "..."],
      "onWrong": ["...", "...", "..."]
    }
  },
  "ending": {
    "win": [{ "text": "かったときの むすび" }],
    "lose": [{ "text": "まけたときの むすび" }]
  }
}
```

`id`・`stage`・`author` は書かなくてよい（こちらで入れる）。

### 数の決まり

| 項目 | 数 |
| --- | --- |
| `pages`（本文） | **16〜24 ページ**（検査は 12〜30） |
| 1 ページの長さ | **160 字以内**。1〜3 文。声に出して 40 秒以内 |
| `cast`（おもな登場人物） | 2〜5 人。1 人目が主人公 |
| `boss.enemy.onCorrect` / `onWrong` | それぞれ 3 つ |
| `ending.win` / `ending.lose` | それぞれ 2〜4 ページ（検査は 1〜5） |

### 守ること

**文章**

- ひらがなとカタカナだけで書く。**漢字を使わない**
- 読点のかわりに 分かち書き（すきまを あける）を使う
- セリフは「」でくくる

**しょうぶ**

- しょうぶ は話の最後の 1 回だけ。本文の中で戦わない
- あいて自身も **かけざんを おぼえている最中**という立場で書く
- `onWrong` には必ず「自分も まちがえる」という趣旨を入れる。子どもを責める言い方をしない
- `ending.win` と `ending.lose` を**両方必ず**書く
- **負けたときの結びを、劣化版にしない。** 負けても話は終わりまで進み、あたたかく終わる。
  「ここで ぼうけんは おわった」「さいしょから やりなおし」は書かない

**出さないもの**

- 「べんきょう」「ドリル」「がくしゅう」「テスト」という言葉
- 点数、ランク、れんぞく記録
- こわすぎる表現、暴力的な表現。寝る前に読むことがある。
  どきどきは「ちょっと こわいけど だいじょうぶ」の範囲まで

### 出力

JSON だけを出力してください。説明文は不要です。
