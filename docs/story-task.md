# 注文された話を作る手順（スケジュールタスク用）

子どもが注文した話を作って、遊べる状態にするまでの手順。

**LLM を API として呼ばない。** 話を書くのは、この手順を実行している Claude 自身である。
従量課金は発生しない。判断の根拠は `docs/story-authoring-design.md`。

## 仕掛け方

Claude Code のセッションで、このリポジトリに対して実行する。
定期実行にするなら、同じ内容の Routine（スケジュールタスク）を作って、
下の「タスクに渡す文面」をそのまま入れる。

親が手で動かしたいときも、同じ文面を投げればよい。

### 必要な環境変数

`.env.local` に置いてあれば自動で読む。無ければセッションの環境変数に入れる。

| 変数 | 中身 |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase のプロジェクト URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | **anon** キー（service_role は使わない） |
| `FAMILY_CODE` | 親画面で設定した合言葉 |

`FAMILY_CODE` だけはアプリ側では端末に入れているので、`.env.local` に足す必要がある。

### 作る時刻を子どもの画面にも書く

親画面の「子どもがつくった おはなし」→「作る時刻」に、
スケジュールタスクを仕掛けた時刻を入れておく。
子どもの画面に「つぎに できるのは ◯じごろ」と出るだけのもので、
ここを変えてもタスクの時刻は変わらない。

## タスクに渡す文面

ここから下をそのままコピーして、Routine の指示文にする。

---

kukuWebApp のリポジトリで、`docs/story-task.md` の「手順」に従って、
注文されたおはなしを作ってください。注文が無ければ何もせず終わってよいです。

---

## 手順

### 1. 注文を見る

```bash
npm run stories -- pending
```

`注文なし` と出たら、ここで終わり。

### 2. 1 件ずつ、指示文を出す

```bash
npm run stories -- prompt <id>
```

`docs/story-prompt.md` の本文に、子どもが出した種（ばしょ・でてくるもの・かんじ・段）を
差し込んだものが出る。**この指示文に従って、あなたが JSON を書く。**

子どもが言ったことを話の中心に使うこと。新しく話を考えるのではなく、
子どもの言葉を話の形にするのが仕事である。

### 3. JSON をファイルに書く

一時ファイルに書く。リポジトリの中には置かない（生成物はリポジトリの資産ではない）。

`id` と `stage` と `author` は書かなくてよい。公開時にこちらで入れ直す。
こちらが知っている事実であって、創作の対象ではない。

### 4. 検査する

```bash
npm run stories -- check <file.json>
```

通らなければ、出た指摘を直して書き直す。よく落ちるのは次の 3 つ。

- 漢字が混ざっている（ひらがな・カタカナ・数字のみ）
- 1 つの文が 100 字を超えている
- 枝ごとの あいて・出会い が 4 つずつ揃っていない

### 5. 公開する

```bash
npm run stories -- publish <id> <file.json>
```

検査に通らなければ書き込まない。通れば子どもの画面に並ぶ。

### 6. どうしても作れなかったとき

```bash
npm run stories -- fail <id> "理由"
```

黙って放置しない。注文が消えたように見えると、子どもは次を注文しなくなる。
失敗として閉じれば、子どもの画面に「うまく できなかったみたい」と出る。

## 守ること

- **1 回の実行で作るのは 3 件まで。** それ以上は次の回に回す
- **怖い表現・暴力的な表現を書かない。** 寝る前に見ることがある
- **「べんきょう」「ドリル」「がくしゅう」「テスト」という言葉を出さない。**
  このアプリは勉強を名乗らない
- **点数・ランク・れんぞく記録を話の中に出さない。** 話は話として閉じる
- **あいては必ず「自分も まちがえる」と言う。** 画面の中に、間違いを責める者を置かない
- **負けたときの話（`outroLose`）を必ず書く。** 勝ったときだけ話が進む形にしない

## うまくいっているかの確認

親画面の「子どもがつくった おはなし」に一覧が出る。
「遊べない」と出ているものは、検査に通っていないか中身が入っていない。
理由がその場に出るので、直して `publish` し直すか、`fail` で閉じる。

読む側（アプリ）でも必ず検査する。手で直接 Supabase を触ることもできる以上、
壊れた話が子どもの画面に出る経路を残していない。
